# Sreda Messenger — уведомления pi-агента в «Среду» (armgs)

Репозиторий содержит связку для отправки уведомлений из pi-агента в корпоративный
мессенджер «Среда» (`webim.armgs.team`):

| Компонент | Роль |
|---|---|
| `extensions/sreda-messenger/` | **TS-расширение** pi-агента: ловит события работы агента (завершение, возобновление) и вызывает skill |
| `skills/sreda_send/` | **Python-skill**: сам токен/подписка (cold OAuth), отправка текста и файлов в «Среду» |

Разделение ответственности строгое: TypeScript **не обращается** к API «Среды» —
весь OAuth/HTTPS/загрузка файлов делает `skills/sreda_send/sreda_send.py`
(загрузка идёт чанками 10 МБ тем же способом, что веб-клиент:
`files/init → upload → files/info → sendIM`).

## Что приходит в мессенджер

| Когда | Что отправляет |
|---|---|
| Агент **окончательно** завершил работу (`agent_settled` + «тихое окно» 3 с без нового выполнения) | Нормальное завершение: 1) текст `Pi-агент. Сессия: <имя> / Работа завершена / <дата время>`; 2) вложение **`message.pdf`** — финальный ответ агента, отрендеренный в PDF (headless Chromium). Остановка из-за ошибки (`stopReason: "error"`): текст `Pi-агент. Сессия: <имя> / Остановлен из-за ошибки / <дата время>` (+ `message.pdf`, если ответ есть) |
| **Субагент** остановился из-за ошибки (pi-процесс с `PI_SUBAGENT_*`; при нормальном завершении молчит) | `Pi - субагент: / <имя субагента> / Сессия: / <имя сессии> / Остановлен из-за ошибки / <дата время>` |
| Агент **возобновил** работу (новое сообщение пользователя в уже не первой сессии) | `Pi-агент. Сессия: <имя> / возобновлена / <дата время>` |

Важные детали логики:

- «Работа завершена» отправляется **только** когда агент по-настоящему «остыл»:
  `ctx.isIdle() === true`, очередь сообщений пуста и за 3 с не стартовало новое
  выполнение (очередное продолжение, steering, авто-ретрай). Если агент продолжил
  работать — уведомление **не** шлётся.
- Продолжение той же работы (сообщение сразу после хода) не порождает ни
  «завершена», ни «возобновлена».
- `TUI`-команды (`/…`) и первое сообщение новой сессии — без уведомлений.
- Если PDF не удалось сформировать (нет node/Chromium) — отправляется только текст.
- При успехе/ошибке TUI получает краткое уведомление `Среда: …`.

### Защита от мусорных уведомлений

- **Субагенты.** Если pi-процесс запущен как субагент (заданы
  `PI_SUBAGENT_ID` / `PI_SUBAGENT_NAME` / `PI_SUBAGENT_SESSION`) — при нормальном
  завершении он **молчит** («завершена»/«возобновлена» шлёт **только основной агент**,
  иначе каждый завершившийся субагент шёл бы своё сообщение с пустым `message.pdf`);
  при остановке **из-за ошибки** субагент шлёт своё короткое сообщение:
  `Pi - субагент: / <имя> / Сессия: / <имя сессии> / Остановлен из-за ошибки / <дата время>`.
- **Ожидание субагента — не окончание.** Если agent запустил fire-and-forget субагента
  и тот ещё не вернул результат, то «Работа завершена» основного агента **подавляется**
  (но текущий ответ уходит отдельным `message.pdf`). Определяется **нетто-счётом по всей
  истории сессии** (функция `hasPendingSubagent`): `+1` за каждый assistant-вызов
  `subagent`/`subagent_resume` (запуск/возобновление), `−1` за каждое
  `subagent_result` (результат доставлен — steer) и `−1` за `subagent_interrupt` (прерван).
  `pending > 0` = есть незавершённый субагент. Fire-and-forget ack (toolResult) **не**
  считается завершением — настоящим завершением является именно `subagent_result`.
  Приход результата считается продолжением работы, не «возобновлением». Финальное
  «Работа завершена» отправляется, когда все запущенные субагенты отработают.

### MUTE — выключить автоматические уведомления

- Переключатель хранится в `extensions/sreda-messenger/.sreda-notify.json`
  (поле `enabled`; `false` = MUTE). Файл в `.gitignore` (локальный тумблер).
- LLM может переключить его tool'ом **`sreda_notify`** (`enabled: true|false`) —
  вызывайте, когда пользователь просит «не присылай сообщений» (= `false`)
  или возобновить (= `true`).
- Вручную:
  ```bash
  # выключить / включить автосообщения
  echo '{"enabled": false}' > ~/.pi/agent/extensions/sreda-messenger/.sreda-notify.json
  rm ~/.pi/agent/extensions/sreda-messenger/.sreda-notify.json   # удалить — снова включены
  ```
- При MUTE в TUI видно `Среда: MUTE — … не отправлено`, в «Среду» ничего не уходит.

## Структура

```
sreda/
├── extensions/sreda-messenger/
│   ├── index.ts          # расширение pi-агента (события, очередь, md2pdf)
│   ├── config.json       # получатель (НЕ секрет)
│   └── README.md
└── skills/sreda_send/
    ├── SKILL.md          # описание skill'а для LLM
    ├── sreda_send.py     # main: token / send (--to, --text, --attach)
    ├── md2pdf.cjs        # md/txt/html → PDF (headless Chromium)
    └── config.json       # логин/пароль «Среды» (СЕКРЕТ, в .gitignore)
```

## Установка

1. Клонируйте репозиторий в постоянный каталог, например
   .pi/agent
3. Заполните оба `config.json` (см. ниже).
4. Проверьте связь (см. «Быстрая проверка»).

Зависимости: `python3`; для PDF-вложений — `node` + Chromium
(при их отсутствии всё работает, но вложения `.md`/`.txt` уходят «сырыми»).

## Настройка — `extensions/sreda-messenger/config.json`

Настройки **расширения**: кому слать уведомления. Не секрет, коммитится в git.

```json
{
  "recipient": "32.klorshteinve@rosstat.gov.ru"
}
```

| Поле | Обязательное | Описание |
|---|---|---|
| `recipient` | да | Полный адрес получателя `login@domain` или `login` — домен приписается по умолчанию `@rosstat.gov.ru` |

Если файла нет или `recipient` пустой — расширение выключается с записью в stderr,
на события `agent_settled`/`input` уведомлений не будет.

## Настройка — `skills/sreda_send/config.json`

Настройки **skill'а** (Python-скрилл): учётные данные «Среды». **Секрет** — файл
в `.gitignore` и не должен попадать в git.

```json
{
  "user": "32.SAD",
  "password": "…",
  "domain": "rosstat.gov.ru",
  "tokenDir": ""
}
```

| Поле | Обязательное | Описание |
|---|---|---|
| `user` | да | Логин «Среды». При отсутствии `user`/`password` скрипт роняет `exit(2)` |
| `password` | да | Пароль «Среды» |
| `domain` | нет | Домен для адресов `--to`, если в них нет `@` (default: `rosstat.gov.ru`) |
| `tokenDir` | нет | Каталог для `state.json` (токен/OAuth). Пустая строка → `<каталог_skill'а>/.sreda/` |

Файл `state.json` в `tokenDir` — кэш сессии (`token` + `aimsid`, TTL ~24 ч).
При истечении скрипт автоматически делает cold OAuth заново; также можно
принудить: `python3 sreda_send.py token`.

## Быстрая проверка из CLI

Не требует запущенного pi-агента:

```bash
# 1) принудительная авторизация (cold OAuth)
python3 skills/sreda_send/sreda_send.py token

# 2) текстовое сообщение
python3 skills/sreda_send/sreda_send.py send \
    --to 32.klorshteinve \
    --text "Проверка связи"

# 3) текст + файлы (в несколько получателей — повторяя --to)
python3 skills/sreda_send/sreda_send.py send \
    --to 32.klorshteinve --to 32.klorshteinn \
    --text "Нашёл ошибки, пришлю файлы" \
    --attach /tmp/report.md --attach /tmp/chart.png
```

- `--to` — повторять на каждого получателя; без `@` дописывается `@<domain>`.
- `--text` и `--attach` — хотя бы один обязателен.
- `--no-pdf` / `SREDAS_NO_PDF=1` — отключить автоконвертацию `md`/`txt` → PDF.
- `--verbose` — подробный лог на stderr (по умолчанию только ошибки).
- В stdout — JSON: `{"ok": true, "sent": [{"to": …, "ok": …}]}`; exit code 0 = успех.

## Безопасность

- `skills/sreda_send/config.json` — логин/пароль: **не коммитить**, не выкладывать.
- `**/.sreda/state.json` — живой токен: тоже не коммитить , не выкладывать.
- Расширение по умолчанию шлёт только в `recipient` из своего `config.json`;
  произвольные получатели возможны только при прямом запуске CLI.
