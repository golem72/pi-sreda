# Sreda Send — отправка сообщений в «Среду»

Python-скрилл: сам выполняет OAuth-вход (если токена нет), отправляет
текст/файлы одному или нескольким получателям. Скрипт живёт рядом с этим SKILL.md
и вызывает **`sreda_send.py`**.

## Команды

```bash
# 1) Принудительное обновление токена (cold OAuth, 8 шагов):
python3 <skill_dir>/sreda_send.py token

# 2) Отправка текста:
python3 <skill_dir>/sreda_send.py send \
    --to 32.klorshteinve \
    --text "Агент pi.dev. Работа завершена (01.09.2026 21:11:53)"

# 3) Текст + файлы:
python3 <skill_dir>/sreda_send.py send \
    --to 32.klorshteinve --to 32.klorshteinn \
    --text "Нашёл ошибки, пришлю файлы" \
    --attach /path/to/report.md --attach /path/to/chart.png
```

- `--to` — повторять на каждого получателя; без `@` дописывает `@rosstat.gov.ru`
  (домен берётся из config.json).
- `--text` и/или `--attach` — хотя бы один обязателен.
- `--verbose` — подробный лог на stderr (по умолчанию только ошибки).
- `--no-pdf` — отключить автоконвертацию md/txt в PDF (см. ниже).
- Файл может быть любого размера: загрузка идёт чанками 10 МБ тем же
  способом, что веб-клиент (`files/init` → `upload` → `files/info` → `sendIM`).
- Итог — JSON в stdout: `{"ok": true, "sent": [{"to": ..., "ok": ...}]}`.
  Exit code 0 = успех.

## Автоконвертация вложений (md/txt → PDF)

Клиенты «Среды» некорректно показывают файлы с «неопознанным» MIME
(сервер даёт `application/octet-stream` для `.md`/`.txt`): на десктопе это
сырая ссылка, на мобильном — скрыто. Поэтому перед отправкой скрипт
конвертирует текстовые вложения в **PDF** (`node md2pdf.cjs`, headless
Chromium): кириллица, заголовки, списки, код, bold/italic, цитаты, ссылки;
имя файла в сообщении становится `<имя>.pdf`.

- Конвертируются расширения: `md`, `markdown`, `txt`, `text`. Остальные
  (pdf, docx, xlsx, png, html, zip) уходят как есть.
- Отключить: `--no-pdf` или `SREDAS_NO_PDF=1`.
- Если конвертер недоступен (нет node/chromium) — без ошибок отправляется
  оригинал, предупреждение в stderr (`--verbose`).
- Ограничение рендера: markdown-таблицы выводятся как текст-строки.
- `html`-вложения конвертируются только при явном вызове `md2pdf.cjs`
  (в `sreda_send.py` html уходит файлом как есть).

## Конфигурация (config.json рядом со скриптом)

```json
{
  "user": "32.SAD",
  "password": "…",
  "domain": "rosstat.gov.ru",
  "tokenDir": ""
}
```

- `user` / `password` — логин и пароль «Среды»;
- `domain` (опц.) — домен для адресов без `@`;
- `tokenDir` (опц.) — каталог для `state.json`; пусто → `<skill_dir>/.sreda/`.

## Токеноведение

- Если `<tokenDir>/state.json` содержит свежий `token`+`aimsid` (TTL 24 h) —
  вход не выполняется, сообщение уходит сразу.
- Иначе — cold OAuth: myteam-config → authorize → login (act) → POST формы →
  code → config → токены → `startSession` (aimsid).
- `token`-команда форсирует ре-авторизацию.

## Расширение `sreda-messenger` (уведомления «Агент pi.dev.»)

- **Окончательное завершение работы агента (остановка)** — пара сообщений отправляется ТОЛЬКО когда
  агент по-настоящему «остыл»: `agent_settled` + `ctx.isIdle()` — true + очередь сообщений
  пуста + в течение «тихого окна» (3 с) не стартовало новое выполнение (очередное
  продолжение, steering, авто-ретрай). Если агент продолжил работу — «Завершена» НЕ шлётся.
  После «остывания»:
  1. текст (переносы строк как заданы; имя сессии — `ctx.sessionManager.getSessionName()`,
     если не задано — «(без названия)»):
     ```
     Pi-агент. Сессия:
     (Имя сессии)
     Работа завершена
     (дата и время отправки)
     ```
  2. вложение **`otvet.pdf`** — финальный ответ агента, отрендеренный в PDF
     (`node <этот каталог>/md2pdf.cjs` + Chromium; если node/Chromium недоступны —
     только текст, ошибка в TUI; если рабочий ответ пуст — только текст).

- **Возобновление работы агента** — новое сообщение пользователя в сессии, где уже есть
  хотя бы один ответ ассистента, и агент не занят; текст:
  ```
  Pi-агент. Сессия:
  (Имя сессии)
  возобновлена
  (дата и время отправки)
  ```
  Если сообщение пришло сразу после хода (в тихом окне) — это продолжение той же работы,
  уведомлений нет. Первое сообщение новой сессии и TUI-команды (`/…`) — тоже без уведомлений.

- Получатель: `extensions/sreda-messenger/config.json` → `32.klorshteinve@rosstat.gov.ru`.

## Важно

- `state.json` и `config.json` — секреты: не выкладывать, не коммичить
  (добавлено в `.gitignore`).
- `config.json` обязателен; при отсутствии `user`/`password` скрипт роняет
  `exit(2)` с понятным сообщением.
